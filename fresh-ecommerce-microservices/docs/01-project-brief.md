# 生鲜电商微服务系统项目说明

## 项目目标

本项目用于学习 vibe coding，而不是深入手写每一行代码。

我希望通过这个项目理解一个生鲜电商系统如何从业务想法拆解成后端 API，并学习如何向 AI 描述需求、检查接口设计、验证接口是否可用。

## 项目形态

项目最终包含两个使用入口：

- 买家端：用于浏览商品、加入购物车、下单、查看订单和物流状态。
- 后台管理端：用于管理商品、批次、库存、订单、物流状态和运营数据。

## 项目完成标准

本项目是学习 Demo，目标是让核心功能跑通即可。

暂时不追求：

- 真实支付
- 真实物流
- 高并发
- 秒杀
- 优惠券
- 复杂权限系统
- 自动定价
- 损耗预测

## 核心业务关注点

这个项目虽然是学习 Demo，但希望体现生鲜电商和普通电商的区别。

买家端除了浏览商品、加入购物车、创建订单、查看订单之外，还需要在商品浏览和详情场景中看到商品的新鲜度相关信息：

- 商品产地
- 捕捞时间
- 运输到店时间

后台管理端除了添加商品、修改库存、查看订单、修改订单状态之外，还希望看到：

- 运输中损耗率
- daily market price
- 物流状态
- 质检状态

这些信息的目标不是一开始就做复杂算法，而是先通过 API 字段展示出来，让学习者理解后端接口如何承载业务信息。

## 商品范围

第一阶段项目以海鲜商品为主，例如鱼、虾、蟹、贝类。

因为海鲜商品对新鲜度要求较高，所以买家端商品信息需要展示：

- 商品产地
- 捕捞时间
- 运输到店时间

果蔬、肉禽蛋奶等其他生鲜品类暂时不作为第一阶段重点。

## 第一阶段核心闭环

第一阶段选择完整学习闭环：

> 后台录入批次和价格 -> 买家下单 -> 后台发货 -> 记录损耗 -> 买家查看物流

这个闭环的目标不是做复杂业务，而是帮助学习者理解后端 API 如何支撑一个真实业务流程。

### 业务流程

1. 后台创建海鲜商品。
2. 后台录入商品批次，包括产地、捕捞时间、到店时间、库存数量。
3. 后台维护 daily market price，作为当天进货参考价。
4. 买家浏览商品，并看到产地、捕捞时间、到店时间等新鲜度信息。
5. 买家加入购物车并创建订单。
6. 后台查看订单并安排发货。
7. 后台更新物流状态。
8. 后台在商品到货或订单送达后，记录该商品批次的实际运输损耗率。
9. 买家查看订单和完整物流轨迹。

## 第一阶段核心对象

第一阶段保留 3 个核心对象：

- Product：商品
- ProductBatch：商品批次
- Order：订单

为了降低学习复杂度，以下信息暂时不设计成独立对象：

- daily market price：先作为 ProductBatch 的字段。
- 物流状态：先作为 Order 的字段。
- 运输损耗率：先作为 ProductBatch 的字段。

### Product 商品

Product 表示海鲜商品本身，例如：

- 舟山带鱼
- 波士顿龙虾
- 青岛蛤蜊

Product 主要回答：

- 这是什么商品？
- 属于什么分类？
- 展示给买家的名称、图片、描述是什么？
- 买家售价是多少？
- 是否上架？

### ProductBatch 商品批次

ProductBatch 表示某个商品的一批进货记录，例如：

- 2026-06-23 到店的一批舟山带鱼
- 产地：浙江舟山
- 捕捞时间：2026-06-22 04:00
- 到店时间：2026-06-23 09:00
- 可售库存：100 份
- daily market price：28 元/斤
- 运输损耗率：3%
- 质检状态：通过

ProductBatch 主要回答：

- 这一批货从哪里来？
- 什么时间捕捞？
- 什么时间到店？
- 当前还有多少库存？
- 运输过程中损耗了多少？
- 后台参考进货价是多少？
- 是否通过质检？

### Order 订单

Order 表示买家下单记录。

Order 主要回答：

- 谁买了什么？
- 买了多少？
- 订单金额是多少？
- 当前订单状态是什么？
- 当前物流状态是什么？
- 物流轨迹是什么？

## 商品与批次的关系

后台先创建 Product，再为 Product 创建 ProductBatch。

Product 表示商品基础信息，例如名称、分类、图片、描述、买家售价、是否上架。

ProductBatch 表示某一批进货信息，例如产地、捕捞时间、到店时间、库存、daily market price、运输损耗率、质检状态。

商品可以先创建但暂时没有批次。例如后台可以先录入“舟山带鱼”这个商品，等实际进货后再录入批次。

买家端看到和购买的是 Product，但后端在创建订单时，需要自动选择一个可售的 ProductBatch，并扣减对应批次库存。

如果一个商品有多个可售批次，第一阶段不让买家选择批次，由后端自动选择一个可售批次。

第一阶段支持管理：

批次管理页是本项目的生鲜业务核心。

第一阶段支持管理：

其中：

- 运输损耗率按商品批次记录。

订单管理页用于后台处理买家订单。

第一阶段支持：

### 简单运营看板

后台需要一个简单运营看板，用于快速了解当前经营情况。

第一阶段看板展示：

- 今日订单数
- 库存不足商品或批次
- 批次运输损耗率

## API 文档学习方式

本项目的 API 文档采用“先业务解释，再接口格式”的方式。

每个接口需要说明：

- 这个接口解决什么业务问题
- 哪个页面会调用它
- 请求方法和接口路径
- 请求参数
- 返回示例
- 前端拿到返回数据后如何展示

第一阶段 API 不追求覆盖所有功能，只覆盖完整学习闭环中必须使用的接口。

## 买家端 API 行为规则

商品列表页展示所有已上架商品。

如果商品没有可售批次，或者可售批次库存为 0，买家端仍然可以看到商品，但需要标注“暂时无货”。

商品详情页展示商品基础信息，并展示一个推荐批次的新鲜度信息。

如果一个商品有多个可售批次，第一阶段选择“最早到店但仍可售”的批次展示。这样可以模拟生鲜业务中的先进先出逻辑，减少旧批次积压。

买家创建订单时，后端实际扣减的是商品批次库存。

如果库存不足，接口返回下单失败，并提示“库存不足”。

第一阶段不做真实支付。订单创建成功后，订单状态直接进入 `PENDING_SHIPMENT`。

## 物流与损耗规则

第一阶段订单物流状态包括：

- `PENDING_SHIPMENT`：待发货
- `SHIPPED`：已发货
- `IN_TRANSIT`：运输中
- `DELIVERED`：已送达

后台维护物流轨迹时，每条轨迹记录包含：

- 状态
- 时间
- 地点
- 备注

运输损耗率按商品批次记录。

第一阶段在商品到货或订单送达后，由后台记录实际运输损耗率。

买家订单详情页显示完整物流轨迹，方便学习后端如何返回订单履约过程数据。

## 第一阶段 API 草案

### 后台创建商品

#### 业务解释

后台运营人员先创建一个商品，让系统知道“我们要卖什么”。

这个接口只创建商品基础信息，不处理库存和批次。

#### 页面使用

后台商品管理页点击“新增商品”时调用。

#### 接口

```http
POST /api/admin/products
```

#### 请求参数示例

```json
{
  "name": "舟山带鱼",
  "category": "海鲜",
  "imageUrl": "https://example.com/hairtail.jpg",
  "description": "来自浙江舟山的冷链带鱼",
  "salePrice": 39.9,
  "isActive": true
}
```

#### 返回示例

```json
{
  "id": "prod_1001",
  "name": "舟山带鱼",
  "category": "海鲜",
  "imageUrl": "https://example.com/hairtail.jpg",
  "description": "来自浙江舟山的冷链带鱼",
  "salePrice": 39.9,
  "isActive": true,
  "createdAt": "2026-06-23T10:00:00+08:00"
}
```

#### 前端如何使用

后台商品管理页提交表单后，调用该接口。

接口成功后，页面可以跳转回商品列表，或者提示“商品创建成功”。

### 后台创建商品批次

#### 业务解释

后台运营人员在商品进货后，为某个商品创建一条批次记录。

批次记录用于管理生鲜商品的新鲜度、库存、进货参考价、损耗率和质检状态。

#### 页面使用

后台批次管理页点击“新增批次”时调用。

#### 接口

```http
POST /api/admin/product-batches
```

#### 请求参数示例

```json
{
  "productId": "prod_1001",
  "batchNo": "BATCH-20260623-001",
  "origin": "浙江舟山",
  "catchTime": "2026-06-22T04:00:00+08:00",
  "arrivalTime": "2026-06-23T09:00:00+08:00",
  "stockQuantity": 100,
  "dailyMarketPrice": 28.5,
  "lossRate": 0.03,
  "qualityCheckStatus": "PASSED"
}
```

#### 返回示例

```json
{
  "id": "batch_2001",
  "productId": "prod_1001",
  "batchNo": "BATCH-20260623-001",
  "origin": "浙江舟山",
  "catchTime": "2026-06-22T04:00:00+08:00",
  "arrivalTime": "2026-06-23T09:00:00+08:00",
  "stockQuantity": 100,
  "dailyMarketPrice": 28.5,
  "lossRate": 0.03,
  "qualityCheckStatus": "PASSED",
  "createdAt": "2026-06-23T10:30:00+08:00"
}
```

#### 前端如何使用

后台批次管理页提交表单后调用该接口。

接口成功后，后台可以在批次列表里看到该批商品，并且买家端商品详情页可以展示对应的新鲜度信息。

### 买家查看商品列表

#### 业务解释

买家进入商品列表页时，需要看到所有已上架商品。

商品列表页只展示简要信息，包括商品名称、图片、分类、买家售价、产地和库存状态。

#### 页面使用

买家端商品列表页加载时调用。

#### 接口

```http
GET /api/products
```

#### 返回示例

```json
{
  "items": [
    {
      "id": "prod_1001",
      "name": "舟山带鱼",
      "category": "海鲜",
      "imageUrl": "https://example.com/hairtail.jpg",
      "salePrice": 39.9,
      "origin": "浙江舟山",
      "stockStatus": "IN_STOCK"
    },
    {
      "id": "prod_1002",
      "name": "梭子蟹",
      "category": "海鲜",
      "imageUrl": "https://example.com/crab.jpg",
      "salePrice": 59.9,
      "origin": "浙江舟山",
      "stockStatus": "OUT_OF_STOCK"
    }
  ]
}
```

#### 前端如何使用

商品列表页用这个接口渲染商品卡片。

如果 `stockStatus` 是 `OUT_OF_STOCK`，页面显示“暂时无货”，并禁用加入购物车或下单按钮。

### 买家查看商品详情

#### 业务解释

买家点击商品后，需要看到商品基础信息和新鲜度信息。

详情页会展示一个推荐批次的信息。第一阶段推荐规则是：选择最早到店但仍可售的批次。

#### 页面使用

买家端商品详情页加载时调用。

#### 接口

```http
GET /api/products/{productId}
```

#### 返回示例

```json
{
  "id": "prod_1001",
  "name": "舟山带鱼",
  "category": "海鲜",
  "imageUrl": "https://example.com/hairtail.jpg",
  "description": "来自浙江舟山的冷链带鱼",
  "salePrice": 39.9,
  "stockStatus": "IN_STOCK",
  "recommendedBatch": {
    "batchNo": "BATCH-20260623-001",
    "origin": "浙江舟山",
    "catchTime": "2026-06-22T04:00:00+08:00",
    "arrivalTime": "2026-06-23T09:00:00+08:00",
    "stockQuantity": 100,
    "qualityCheckStatus": "PASSED"
  }
}
```

#### 前端如何使用

商品详情页展示商品基础信息。

`recommendedBatch` 用于展示产地、捕捞时间、到店时间、质检状态等新鲜度信息。

daily market price 和运输损耗率不返回给买家端。

### 买家创建订单

#### 业务解释

买家提交订单时，前端只需要告诉后端买了哪个商品和数量。

后端会自动选择可售批次，并扣减对应批次库存。

如果库存不足，接口返回失败。

第一阶段不做真实支付，订单创建成功后状态直接为 `PENDING_SHIPMENT`。

#### 页面使用

买家端下单页点击“提交订单”时调用。

#### 接口

```http
POST /api/orders
```

#### 请求参数示例

```json
{
  "items": [
    {
      "productId": "prod_1001",
      "quantity": 2
    }
  ],
  "receiverName": "张三",
  "receiverPhone": "13800000000",
  "receiverAddress": "上海市浦东新区示例路 100 号"
}
```

#### 成功返回示例

```json
{
  "id": "order_3001",
  "orderStatus": "PENDING_SHIPMENT",
  "totalAmount": 79.8,
  "items": [
    {
      "productId": "prod_1001",
      "productName": "舟山带鱼",
      "quantity": 2,
      "salePrice": 39.9,
      "batchNo": "BATCH-20260623-001"
    }
  ],
  "createdAt": "2026-06-23T11:00:00+08:00"
}
```

#### 库存不足返回示例

```json
{
  "error": "INSUFFICIENT_STOCK",
  "message": "库存不足，请减少购买数量"
}
```

#### 前端如何使用

下单页提交商品和收货信息。

如果成功，页面跳转到订单详情页。

如果返回 `INSUFFICIENT_STOCK`，页面提示库存不足。

### 后台查看订单列表

#### 业务解释

后台需要查看买家提交的订单，并决定是否发货。

#### 页面使用

后台订单管理页加载时调用。

#### 接口

```http
GET /api/admin/orders
```

#### 返回示例

```json
{
  "items": [
    {
      "id": "order_3001",
      "orderStatus": "PENDING_SHIPMENT",
      "logisticsStatus": "PENDING_SHIPMENT",
      "totalAmount": 79.8,
      "receiverName": "张三",
      "createdAt": "2026-06-23T11:00:00+08:00"

  ]
}
```

#### 前端如何使用

后台订单管理页用这个接口渲染订单列表。

运营人员可以根据订单状态决定是否更新物流。

### 后台更新订单物流

#### 业务解释

后台发货或更新配送进度时，需要修改订单的物流状态，并追加一条物流轨迹。

#### 页面使用

后台订单管理页点击“更新物流”时调用。

#### 接口

```http
PATCH /api/admin/orders/{orderId}/logistics
```

#### 请求参数示例

```json
{
  "logisticsStatus": "IN_TRANSIT",
  "trackedAt": "2026-06-23T15:00:00+08:00",
  "location": "上海冷链分拨中心",
  "note": "订单已进入冷链运输"
}
```

#### 返回示例

```json
{
  "id": "order_3001",
  "orderStatus": "PENDING_SHIPMENT",
  "logisticsStatus": "IN_TRANSIT",
  "logisticsTracks": [
    {
      "status": "SHIPPED",
      "trackedAt": "2026-06-23T13:00:00+08:00",
      "location": "门店仓",
      "note": "订单已发货"
    },
    {
      "status": "IN_TRANSIT",
      "trackedAt": "2026-06-23T15:00:00+08:00",
      "location": "上海冷链分拨中心",
      "note": "订单已进入冷链运输"
    }
  ]
}
```

#### 前端如何使用

后台订单管理页提交新的物流状态、时间、地点和备注。

接口成功后，订单详情页和买家订单详情页都可以看到更新后的物流轨迹。

### 后台记录批次损耗率

#### 业务解释

商品到货或订单送达后，后台记录该商品批次的实际运输损耗率。

损耗率属于后台运营字段，不展示给买家。

#### 页面使用

后台批次管理页或运营看板中更新损耗率时调用。

#### 接口

```http
PATCH /api/admin/product-batches/{batchId}/loss-rate
```

#### 请求参数示例

```json
{
  "lossRate": 0.035,
  "note": "运输过程中部分包装破损，实际损耗率为 3.5%"
}
```

#### 返回示例

```json
{
  "id": "batch_2001",
  "batchNo": "BATCH-20260623-001",
  "lossRate": 0.035,
  "updatedAt": "2026-06-23T18:00:00+08:00"
}
```

#### 前端如何使用

后台批次管理页或运营看板提交实际损耗率。

接口成功后，后台可以在批次列表和运营看板中看到更新后的损耗率。

### 买家查看订单详情和物流轨迹

#### 业务解释

买家下单后，需要查看订单详情和完整物流轨迹。

#### 页面使用

买家订单详情页加载时调用。

#### 接口

```http
GET /api/orders/{orderId}
```

#### 返回示例

```json
{
  "id": "order_3001",
  "orderStatus": "PENDING_SHIPMENT",
  "logisticsStatus": "IN_TRANSIT",
  "totalAmount": 79.8,
  "items": [
    {
      "productName": "舟山带鱼",
      "quantity": 2,
      "salePrice": 39.9
    }
  ],
  "receiverName": "张三",
  "receiverPhone": "13800000000",
  "receiverAddress": "上海市浦东新区示例路 100 号",
  "logisticsTracks": [
    {
      "status": "SHIPPED",
      "trackedAt": "2026-06-23T13:00:00+08:00",
      "location": "门店仓",
      "note": "订单已发货"
    },
    {
      "status": "IN_TRANSIT",
      "trackedAt": "2026-06-23T15:00:00+08:00",
      "location": "上海冷链分拨中心",
      "note": "订单已进入冷链运输"
    }
  ]
}
```

#### 前端如何使用

买家订单详情页展示订单商品、金额、收货信息、当前物流状态和完整物流轨迹。

运输损耗率不返回给买家端。
