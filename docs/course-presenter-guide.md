# 中文 LLM Agent 课程演示讲稿

这份文档用于现场演示或录屏。目标是让讲者按固定路径走完整站点，既能讲清每页的核心概念，也能知道应该点击哪里、预期看到什么。

## 演示前准备

- 打开本地或线上站点首页。
- 确认右上角显示“模拟模式”，这样不依赖真实 LLM API，也不会因为网络或 API Key 影响课程演示。
- 课程页有两个主要区域：
  - “学习”：阅读讲解、查看代码、运行完整代码。
  - “运行”：点击样例输入，看右侧图谱、Trace 日志和回放动画。
- 注意：“运行完整代码”执行的是整段示例代码，输出显示在代码块下方；要看逐步动画，请进入“运行”页点击样例按钮。

## 首页

路线：`/`

讲稿：

欢迎大家来到这套 LLM Agent 交互式课程。我们不从框架 API 开始，而是从最小可运行的代码开始。你会看到：Agent 不是玄学，它就是一个函数、一个工具字典、一个循环，再加上状态、记忆、策略和计划执行。

今天的演示会按十节课往下走。每节课都会先讲概念，再点一个样例，让大家看到 Agent 图谱和执行日志是怎么变化的。

2. 如果先进入学习路径页，点击“第 1 课：Agent 就是一个函数”。

预期看到：

- 中文首页文案。
- 没有广告、招聘横幅或第三方追踪提示。
- 可以进入课程学习路径。

这里是十节课的总览。顺序很重要：前几节建立最小 Agent，后几节逐步加入真实产品里常见的能力。学完之后，你再看 LangChain、CrewAI、AutoGen、OpenAI Agents SDK 或 Skill Bundle，会更容易看懂它们到底封装了什么。

点击步骤：

预期看到：

- 十节课按顺序排列。
- 每节课标题和摘要均为中文。

## 第 1 课：Agent 就是一个函数

路线：`/lesson/agent-function`

讲稿：

第一课只讲一件事：Agent 最小形态就是一个函数。输入用户消息，调用 LLM，返回答案。ChatGPT、Claude 的聊天体验，底层都可以先理解成一次请求和一次响应。

这里先不要急着上工具。我们先看最小闭环：用户输入进入 `agent()`，`agent()` 调用 `ask_llm()`，最后把结果返回给用户。

点击步骤：

1. 点击底部“运行”。
2. 点击样例“什么是 AI Agent？”。
3. 观察图谱从“用户”走到“Agent”，再到“LLM”，最后返回。
4. 点击播放/重放按钮，让 Trace 自动走一遍。
5. 点击“下一课”。

预期看到：

- Trace 中出现用户问题。
- Agent 返回中文解释：“AI Agent 是一个用 LLM 决定下一步动作的程序……”

过渡台词：

现在我们已经有了会回答问题的函数。下一步的问题是：如果它需要计算、搜索、读文件怎么办？这就进入工具。

## 第 2 课：工具就是一个字典

路线：`/lesson/tools`

讲稿：

工具调用其实没有那么神秘。LLM 自己不能真正执行代码，它只是返回一个结构化请求，比如“调用 add，参数是 10 和 5”。真正执行的是我们的程序。

所以工具最朴素的形态就是一个字典：`tools[name](**args)`。框架里的 `@tool` 装饰器，底层就是帮你组织这件事。

点击步骤：

1. 点击底部“运行”。
2. 点击样例“计算 10 加 5”。
3. 观察图谱经过“LLM + 工具”“分发工具”“工具结果”。
4. 观察 Trace 中的 `add → 15`。
5. 切回“学习”，可点击一次“运行完整代码”，说明完整代码输出显示在代码块下方。
6. 点击“下一课”。

预期看到：

- 工具结果为 `15`。
- Trace 中有工具调用和 Agent 最终输出。
- 点击“运行完整代码”不会跳到只有“用户/完整代码”的运行页，而是留在学习页显示输出。

过渡台词：

现在 Agent 已经能调用一次工具。但真实任务往往不止一步，下一课就是多步循环。

## 第 3 课：Agent 循环

路线：`/lesson/agent-loop`

讲稿：

Agent 的核心是循环。它会问 LLM：下一步做什么？如果 LLM 要调用工具，我们执行工具，把结果放回消息数组，再问一次 LLM。直到 LLM 不再请求工具，任务才结束。

这就是很多框架里 AgentExecutor 的核心。名字很大，本质就是一个 while 循环。

点击步骤：

1. 点击“运行”。
2. 点击样例“先计算 3 加 4，然后把 hello 转成大写”。
3. 观察 Trace：先调用 `add`，再调用 `upper`。
4. 点击“重放”，展示循环如何一轮一轮推进。
5. 点击“下一课”。

预期看到：

- `add({'a': 3, 'b': 4}) → 7`。
- `upper({'text': 'hello'}) → HELLO`。
- 最终输出“处理后是：HELLO”。

过渡台词：

循环需要保存上下文。否则第二轮不知道第一轮发生了什么。下一课讲消息数组，也就是对话。

## 第 4 课：对话就是消息数组

路线：`/lesson/conversation`

讲稿：

ChatGPT 为什么在同一个对话里记得你刚才问了什么？因为每一轮都会把历史消息带回去。新对话为什么会忘？因为消息数组重新开始了。

这一课要让大家看到：对话不是魔法，就是一个 messages 数组。

点击步骤：

1. 点击“运行”。
2. 点击样例“计算 3 加 4”。
3. 再点击样例“我刚才问了什么？”。
4. 观察 Trace 和输出，说明后一次回答依赖前面的消息历史。
5. 点击“下一课”。

预期看到：

- 第一次输出“结果是 7”。
- 第二次能回答“你刚才让我计算 3 加 4。”

过渡台词：

消息数组能保存对话历史，但生产系统还需要结构化状态。比如已经调用过哪些工具、处理到第几步。

## 第 5 课：状态就是一个字典

路线：`/lesson/state`

讲稿：

状态是对话旁边的结构化记录。比如工具调用次数、当前进度、已读文件、阶段结果。你在 Claude 或 ChatGPT 里看到“搜索了几个文件”“运行了几段代码”，背后通常就有类似状态。

这一课把状态做成一个普通字典，让大家看到每次工具调用都可以更新它。

点击步骤：

1. 点击“运行”。
2. 点击样例“计算 10 加 5，然后把 hello 转成大写”。
3. 观察工具调用结果和状态更新。
4. 如果时间允许，点击“重放”展示状态随步骤变化。
5. 点击“下一课”。

预期看到：

- 先得到 `15`。
- 再得到 `HELLO`。
- Trace 中可以看到多步工具调用和状态相关输出。

过渡台词：

状态通常只在当前运行里有效。那如果要跨会话记住用户偏好或名字，就需要记忆。

## 第 6 课：跨运行的记忆

路线：`/lesson/memory`

讲稿：

记忆和对话历史不一样。对话历史是当前聊天里的上下文，记忆是跨运行、跨会话保存的信息。ChatGPT Memory 和 Claude Projects 里的长期资料，可以先用这个模型理解。

这节课展示最小记忆系统：写入一个键值，再从后续请求里读出来。

点击步骤：

1. 点击“运行”。
2. 点击样例“我的名字是 Alice”。
3. 点击样例“我的名字是什么？”。
4. 观察系统先写入 `name=Alice`，后续回答能读出名字。
5. 点击“下一课”。

预期看到：

- Trace 中出现 `saved name=Alice`。
- 后续回答“你的名字是 Alice。”

过渡台词：

Agent 会记住信息、会调用工具，也可能做危险事。生产环境必须加护栏。

## 第 7 课：策略就是护栏

路线：`/lesson/policy`

讲稿：

策略就是 Agent 前后的检查关卡。输入关卡先判断请求能不能进入 LLM；输出关卡判断 LLM 的结果能不能给用户看。

这不是某个框架专属能力。Guardrails、moderation、输出过滤，本质上都是在 Agent 外面包一层规则。

点击步骤：

1. 点击“运行”。
2. 点击样例“计算 10 加 5”，展示正常请求通过关卡。
3. 点击样例“删除所有内容”，展示输入关卡拦截。
4. 观察图谱里策略节点的变化。
5. 点击“下一课”。

预期看到：

- 正常请求输出“结果是 15”。
- 危险请求被拦截，不进入正常工具执行流程。

过渡台词：

前面都是用户给任务，Agent 执行。更复杂的任务需要先拆清楚，再一步步执行。

## 第 8 课：计划与执行

路线：`/lesson/self-scheduling`

讲稿：

这一课讲更清晰的计划与执行。LLM 先调用 `make_plan` 生成步骤列表，再按顺序调用 `execute_step`。这样讲者和学习者都能看清：目标是什么，步骤是什么，每一步执行到了哪里。

很多真实 Agent 产品都会使用这个结构：代码审查先列检查项，研究报告先出提纲，发布准备先生成 checklist。课程里的执行仍然是模拟的，但接口已经解耦，后续可以替换成真实搜索、代码运行或文件操作。

点击步骤：

1. 点击“运行”。
2. 点击样例“帮我规划学习 Agent”。
3. 观察 Trace 中先出现 `make_plan`。
4. 继续观察后续 `execute_step` 按步骤执行。
5. 点击“下一课”。

预期看到：

- Trace 中先出现 `make_plan({'task': '帮我规划学习 Agent'})`。
- 后续出现多个 `execute_step(...)`。
- 最终回答“计划已执行完成”。

过渡台词：

现在我们已经见过函数、工具、循环、对话、状态、记忆、策略和计划执行。下一课先把所有部件合起来，再进入 Skill。

## 第 9 课：把所有部件合起来

路线：`/lesson/the-whole-thing`

讲稿：

这一课把前面所有部件组合成一个完整 Agent：它能读用户输入、调用工具、维护状态、写入记忆、经过策略检查，并在必要时先做计划再逐步执行。

这个实现不追求生产级完整，而是让你看到框架背后的骨架。以后看任何 Agent 框架，都可以问：它的工具表在哪里？循环在哪里？状态在哪里？记忆在哪里？护栏在哪里？

点击步骤：

1. 点击“运行”。
2. 点击样例“记住 name=Alice，然后计算 10 加 5”。
3. 观察先写入记忆，再调用加法工具。
4. 点击样例“我的名字是什么？”，展示记忆读取。
5. 点击样例“为学习 Agent 制定计划”，展示计划与执行。
6. 点击样例“删除数据库”，展示策略拦截。
7. 点击“下一课”。

预期看到：

- `remember({'key': 'name', 'value': 'Alice'}) → saved name=Alice`。
- `add({'a': 10, 'b': 5}) → 15`。
- `Memory: {'name': 'Alice'}`。
- 计划样例会出现 `make_plan` 和 `execute_step`。
- 危险请求被策略拦截。

过渡台词：

到这里，我们已经把一个 Agent 系统拆成了能读懂、能运行、能替换的部件。最后一课继续往上走一层：如何把一组提示词、脚本和参考资料打包成标准 Skill Bundle。

## 第 10 课：Skill 是标准技能包

路线：`/lesson/skills`

讲稿：

工具是一个函数，Skill 是一整套可复用能力。专业的 Skill Bundle 通常是一个目录：`SKILL.md` 写明什么时候用、怎么用，`scripts/` 放确定性程序，`references/` 或 `assets/` 放按需读取的资料。

这一课要强调两件事：第一，不要一次性把所有 skill 的完整内容塞进上下文，而是先索引 `SKILL.md` 的 frontmatter；第二，命中后再加载完整说明，并通过 `run_script(path, payload)` 这类接口运行脚本。课程里是模拟运行，但接口已经为真实沙箱或真实文件系统预留。

点击步骤：

1. 点击“运行”。
2. 点击样例“审查这段函数：def add(a, b): return a - b”。
3. 观察 Trace 中先出现 `Indexed skill: code-review`。
4. 观察策略检查如何匹配 description。
5. 观察 `run_script: scripts/check_review.py` 和脚本结果。
6. 如需收尾，点击“完成”。

预期看到：

- Skill 先被索引，而不是直接全部加载。
- 命中任务后才读取 `SKILL.md`。
- `scripts/check_review.py` 通过模拟接口执行。
- 最终输出指出 `add` 实现成了减法，并建议补测试。

收尾台词：

到这里，Agent 不只会调用单个工具，也能把一组工具、说明、脚本和资料作为标准 Skill 复用。后续如果接真实代码执行、真实搜索、真实 API，只需要替换工具实现、脚本 runner 和 LLM 接口，课程里的架构边界不用重写。

## 讲者检查清单

- 每节课先讲概念，再点样例。
- 不把“运行完整代码”当作动画入口；动画入口是“运行”页里的样例按钮。
- 每节课至少展示一次 Trace 或图谱变化。
- 第 4、6、9 课要强调历史、记忆、状态的区别。
- 第 7 课要同时展示通过和拦截。
- 第 8 课要强调先计划、再执行、最后汇总，避免观众误以为 Agent 是不可检查的黑箱。
- 第 9 课要回扣真实框架：这些概念会被框架包装，但底层边界相同。
- 第 10 课要强调标准 Skill Bundle：`SKILL.md`、渐进加载、脚本接口，以及模拟 runner 可替换成真实沙箱。
